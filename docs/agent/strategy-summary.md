A marked invulnerable target remains seekable and is excluded from the generic invulnerable-avoidance branch for that target only, so the bot moves toward and follows it even inside combat range. Chase combat only hands off to `buildCombatAction()` when the selected id is present in current native/realtime combat targets, is visible, non-invulnerable, and attackable now; snapshot/minimap data is never used for combat target, aim, or fire.
  - actual chase attacks carry `chaseMode` metadata into attack history. Post-attack drop coin pickup remains prioritized before the next chase step, and active chase kills can use the same short post-attack drop-wait path that AFK Drop kills use while waiting for the dropped coin to appear.
- Coin movement:
  - far aligned coin movement uses dominant-axis approach to reduce snaking;
  - near target handoff/brake prevents overshooting;
  - close pickup uses shorter brake pulses and clears stale axis locks at exact tolerance.
  - pickup pulses now shorten by distance bands as the bot nears the coin coordinate, and repeated close pickup misses further reduce pulse length before giving up on the coin.
- Combat:
  - defensive combat beats normal coin logic when a real threat exists;
  - non-whitelisted, non-invulnerable Active enemies inside `combatAttackRange` remain defensive combat targets only when they are real threats or have worthwhile Drop. Active targets with `Drop <= combatLowValueActiveDropMax = 4` are ignored for proactive combat and profit combat unless they own an incoming bullet, an unknown incoming bullet is paired with their firing signal, or recent injury evidence makes them the likely shooter. This keeps the proactive line at `Drop >= 5`, matching the observed `20` stamina per normal coin and roughly `100` stamina per active-player kill break-even;
  - proactive Active combat also requires enough remaining long-cycle stamina to cover `combatProactiveActiveKillStaminaBudgetMs = 100000`. Once a high-Drop Active target is already engaged and still native/realtime/render visible inside `combatAttackRange`, the long-cycle budget gate no longer clears that in-range engagement into recovery; combat can continue until normal combat fire/reserve rules, stop-loss, disengage, or long-window stamina exhaustion take over;

  - close combat backs away while shooting inside the shorter 45m spacing threshold;
  - combat logging analysis showed 105-145m fights had very poor hit yield versus 30-75m, so default combat spacing now favors 45-65m instead of 75-105m;
  - when an active duel stays beyond 100m for at least 6s without target damage and self HP is not already meaningfully behind, the bot presses toward 75m first instead of treating the long-range exchange as a reason to retreat or spend extra dodge reserve on more shots; this far no-damage close-in branch stays disabled for ordinary retreating-edge targets, but reopens as `retreating-fighter-close` when that retreating target is still creating real target-owned bullet pressure and the HP gate remains favorable;
  - passive coin-runner combat is recognized by explicit combat intent (`defensive`, `engaged`, `profit`, or `reengage`), high self HP, no recent self damage, no real incoming bullet, no target firing, target movement, and a positive Drop/reward signal. This branch now also requires at least `combatPassiveRunnerConfirmMs = 2500` of sustained engagement before it activates, and it is disabled for the rest of that engagement once the target has been seen owning a real incoming bullet. For these targets the bot removes synthetic `target-pressure` dodge, prefers zero-spread live intercept aim against realtime/native visible coordinates, and uses a dedicated 45m close-in move when finish-pressure, retreating-edge, far-no-damage, and ordinary no-damage pressure are not already active;
  - passive coin-runner combat also uses a low no-threat shooting reserve (`combatShootPassiveRunnerDodgeReserveMs = 1800`) while the target is eligible, so high-HP safe runner fights can keep firing during close-in movement instead of repeatedly pausing under the ordinary dodge reserve;
  - confirmed passive coin-runners inside `combatPassiveRunnerPrecisionRange = 5500cm` use live/native/render precision instead of full intercept lead while target damage remains recent. If a moving passive runner reaches `combatPassiveRunnerPrecisionMaxNoDamageMs = 8000` without target damage, close precision is disabled and the bot returns to live intercept so it does not keep shooting at the runner's current coordinate while the target continues moving. Farther passive runners still use live intercept.
  - new Active engagements use an opponent-probe shooting window before target-owned real-bullet evidence is seen. For the first `combatOpponentProbeMs = 6000`, combat preserves a high 5s reserve (`combatOpponentProbeReserveMs = 5600`) and limits fire to `combatOpponentProbeEveryMs = 520`, while movement/spacing/dodge action reasons remain visible. The probe does not override confirmed passive-runner, low-threat finish, or target-owned pressure windows;
  - if the same combat target has no HP damage for at least 8s and self HP is at least 60, the bot pressures closer toward 65m while preserving real-bullet dodge priority;
  - low HP plus long no-damage is not a standalone exit trigger; combat continues unless critical HP, low-HP disadvantage, close-pressure disadvantage, or confirmed high-HP/trade disadvantage thresholds fire;
  - new combat targets enter only inside `combatAttackRange`; an already engaged target remains a combat target until it exceeds `combatDisengageRange`, and while it is outside attack range the bot usually holds position/recovery instead of chasing with `combat-reengage`; the exception is a guarded slight overshoot window up to 150m where an engaged/reengage target can be stepped back into range without shooting if self HP is still healthy, the HP gap is not already bad, and the target is still applying real target-owned bullet pressure or has only just slipped out of range without a retreat signal. Target-owned bullet pressure gets a wider recoverable HP-gap band than ordinary fresh-contact reengage, so a still-fighting target that just crossed the 145m attack boundary can be pressed back into range before stop-loss is considered;

  - if that retreating edge target is already low HP while self is still high HP, the bot uses `combat-finish-pressure`: it moves closer toward the target inside the 145m attack range and allows low-frequency finish shots; if a recently damaged low-HP target slips just outside attack range but remains within 160m, `combat-finish-reengage` moves back into range without shooting out of range, while ordinary healthy/outdated out-of-range targets still hold.

Unsafe straight-on pressure keeps the old pure dodge behavior, and out-of-range safe-close movement still keeps `shoot=false`.
  - if a live combat target is already down to low HP, self HP stays high, the HP gap is not worse than even, the target remains within the guarded finishing range, and there is no real incoming bullet pressure, the bot can enter a `finish-low-threat` fire window that keeps burst fire pressure while using a reduced dodge reserve instead of the normal conservative reserve band;
  - when the current target is the owner of real incoming bullet pressure, self HP is at least 60, the HP gap is not already worse than 10, and distance is within 145m, combat can keep pressure fire active while still preserving the dodge reserve floor. If the same target-owned pressure continues with self HP at most 70, the target ahead by at least 10 HP, and no target damage for 10s, combat exits via `combat-hp-disadvantage-leave` as a later stop-loss after the reengage/pressure options have had room to work;
